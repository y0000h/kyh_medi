## ⚠️ 03 챗봇 응답 검증 — emulator 부하로 실패, 실기기로 넘김

### 시도한 것

1. cold boot 후 도움 탭 → EditText 탭 → `input text "hello"` → "h"만 들어감 (subsequent chars dropped — Flutter `TextField`가 IME composition 통해 받는데, `input text`가 첫 char만 plumb됨)
2. "h"만으로 send 버튼 탭 → 12초 대기 → 앱 ANR ("KYH 약 알림 isn't responding")
3. Wait 버튼 → 여전히 ANR. Close.

### 원인 분석 — 네트워크 X, 시스템 부하 O

- 네트워크 정상: `dumpsys connectivity` → CELLULAR/WIFI 둘 다 VALIDATED, `ping 8.8.8.8` 평균 287ms 성공
- 시스템 부하: cold boot 직후 메모리 1967/2013MB 사용 (98%), iowait 22% — Flutter app + Gemini API call (HTTP+JSON parse) + GBoard + GMS 동시 → ANR 임계값 5초 초과
- emulator 한계로 결론. 실기기에서는 동일 빌드로 챗봇 응답 정상 (추정)

### 함정 — Flutter EditText에 텍스트 주입

`input text "hello"`가 Android EditText면 풀스트링 들어가지만 Flutter `TextField`는 첫 char만 받음. 챗봇 응답 검증을 굳이 emulator에서 해야 한다면 다음 옵션:

- 한 글자씩 sleep 끼워서 보내기: `for c in h e l l o; do "$ADB" shell input text "$c"; sleep 0.3; done`
- ADBKeyboard IME 설치 후 broadcast intent로 텍스트 주입: `am broadcast -a ADB_INPUT_TEXT --es msg "hello"`
- 클립보드 채우기 → long-press paste

### 함정 — `adb pull` 목적지 경로

Git Bash의 `/c/Users/...` 형식은 adb.exe(Windows binary)가 못 읽음. `adb pull` destination은 항상 `c:/Users/...` 형식 사용. (어제 RESUME에는 이미 그렇게 적혀있었지만 오늘 잘못 쓴 명령이 한 번 실패했음)

### 함정 — 첫 cold boot 후 ~30초 ANR 폭풍

Pixel_7 emulator cold boot 직후:
- com.google.android.gms.persistent ANR (geocode service, 22초)
- com.android.chrome ANR
- com.android.vending ANR
- com.google.android.as.oss ANR
- com.google.android.gms ANR (D2dTransportService)
- com.google.android.settings.intelligence ANR
- com.google.android.apps.nexuslauncher 자체 크래시 (IllegalStateException, 메시지 큐 sync barrier)

이 상태에서 monkey 보내면 `cmd: Failure calling service package: Broken pipe (32)`. **Launcher 복구 (`mCurrentFocus=...nexuslauncher.NexusLauncherActivity`) 확인 후** 앱 launch.
