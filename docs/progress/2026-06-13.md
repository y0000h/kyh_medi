## 배경

- 6/10 이후 코드/기능은 출시 수준이었고, 남은 건 외부 콘솔 작업뿐. 그중 5/14·6/10 기록에 미완료로 남아 있던 **"Supabase 이메일 OTP 발송/템플릿"**이 오늘의 핵심 과제였다.

## 흐름

### 1. 양 플랫폼 기동 + 부모 흐름 자동 검증

- Android 에뮬레이터(`kyh_pixel`, API 35) + iOS 시뮬레이터(`iPhone 17`, iOS 26.5) 동시 기동, 모드 선택 화면 양쪽 정상.
- `integration_test/app_test.dart` 양 플랫폼 실행 → **부모 14단계 + 자녀 렌더/검증 All passed**.

### 2. 자녀 실제 OTP 로그인 — Android 먼저

- 라이브 앱을 adb로 구동(자녀세요? → 이메일 탭 → 이메일 입력 → 인증번호 받기).
- 메일 미도착 → Supabase Auth 로그 확인: 발송은 200이나 내장 메일러(`noreply@mail.app.supabase.io`) 레이트리밋/스팸 문제.
- 임시로 **service_role Admin API `generate_link`로 6자리 OTP를 직접 생성**해 입력 → **Android 자녀 로그인 성공**(자녀 홈 "부모님 모니터링" 진입, 페어링 전 빈 상태 정상).

### 3. 무료 커스텀 SMTP(Brevo) 연결 — 근본 해결

- 내장 메일러 한도는 무료/유료 무관 하드캡 → **Brevo 무료 SMTP**(일 300통) 연결로 해결(요금제 무관, 결제 없음).
- iOS 자동화는 `idb`(facebook/fb tap) 설치해 좌표 탭/클립보드 붙여넣기로 구동. (iOS 시뮬레이터 한글 IME가 ASCII 입력을 한글로 변환하는 이슈 → 이메일은 `simctl pbcopy` + 길게 눌러 Paste로 우회)
- **Supabase Management API(PAT)로 Auth 설정 자동 적용**:
  - SMTP: `smtp-relay.brevo.com:587`, user `ae938a001@smtp-brevo.com`
  - `rate_limit_email_sent` 2 → 100
  - **발신 주소 `smtp_admin_email` = `y0000h2@gmail.com`** (Brevo Verified 발신자와 일치)
  - 메일 제목 한글화. (Magic Link 템플릿엔 이미 `{{ .Token }}` 6자리 코드 포함, `uri_allow_list`에 `kyhmedi://auth-callback` 이미 포함)
- **함정**: 실제 메일은 0이 네 개인 `y0000h2@gmail.com`. 그동안 0 세 개(`y000h2`)로 발신/수신해 Brevo가 미인증 발신자로 거부하던 게 진짜 원인. 발신·수신 모두 0 네 개로 통일하니 해결.
  - (Management API 주의: SMTP 필드는 **전부 한 번에** PATCH해야 함. 단일 필드 PATCH는 SMTP 블록 전체를 None으로 초기화.)

### 4. iOS 실제 OTP 로그인 성공

- iOS에서 `y0000h2@gmail.com`로 발송 → **실제 메일 도착**(제목 "KYH 약 알림 — 인증번호", 본문 6자리) → 코드 입력 → **iOS 자녀 로그인 성공**(자녀 홈 진입).

### 5. 코드 갭 수정 — iOS 딥링크 스킴

- 검증 중 발견: **iOS `Info.plist`에 `kyhmedi` URL 스킴 미등록**(Android 매니페스트엔 있음). 6자리 OTP 경로엔 무관하나, 메일 매직링크 폴백이 iOS에서 앱을 못 엶.
- [ios/Runner/Info.plist](../../ios/Runner/Info.plist)에 `CFBundleURLTypes`(scheme `kyhmedi`) 추가 — Android와 동일.
