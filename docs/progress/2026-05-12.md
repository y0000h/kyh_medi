## ✅ 완료 — 디자인 spec deep migration

5/5 spike에서 단일 `tokens.dart`에 통합했던 토큰을 spec 명세대로 폴더 구조 + ThemeExtension + primitive widget으로 마저 분할. 사용자가 "폰 연결 빼고 묻지 말고 쭉 진행" 지시 → auto.

### 토큰 폴더 분할

`lib/core/theme/tokens.dart` 단일 파일 → 폴더 + barrel:

```
core/theme/
├── tokens/
│   ├── colors.dart       # AppColors (senior + caregiver 팔레트)
│   ├── spacing.dart      # AppSpacing (4pt grid)
│   ├── radius.dart       # AppRadius
│   ├── shadows.dart      # AppShadows
│   ├── sizes.dart        # AppSizes (모드별 폰트/버튼)
│   └── typography.dart   # SeniorTypography / CaregiverTypography
├── semantic_colors.dart  # AppSemanticColors ThemeExtension
├── senior_theme.dart
├── caregiver_theme.dart
└── tokens.dart           # barrel — 기존 import 경로 그대로 유지
```

barrel 패턴이라 18개 consumer (`features/...`, `shared/widgets/...`)의 `import '...theme/tokens.dart'`는 한 줄도 안 바뀜.

### AppSemanticColors ThemeExtension

Material `ColorScheme`에 자리 없는 `success` / `danger` / `warning` / `border` / `ink2` / `inkMute`를 ThemeExtension으로:

- `AppSemanticColors.senior` / `AppSemanticColors.caregiver` 두 인스턴스를 각 ThemeData의 `extensions:`에 등록.
- 헬퍼 `AppSemanticColors.of(context)` 로 짧게 접근.
- 활성 테마에 따라 자동 분기 → `StatusBadge`의 `isCaregiver = colorScheme.primary == AppColors.caregiverPrimary` 수동 분기 삭제.

`AppColors.jade/care/capsule` static 참조는 부모 전용 화면(`history_calendar_screen.dart` 등)에서는 유지 — 부모 팔레트 hardcode가 의도된 곳이고 acceptance criteria 5번(hex literal grep gate)도 통과 상태라 무해.

### SectionCard primitive

`shared/widgets/section_card.dart` — `Card + InkWell + Padding` 보일러플레이트 캡슐화. 기본 padding `AppSpacing.xl`(20), `onTap`이면 InkWell + 카드 전체 ripple. 신규 화면에서 채택, 기존 화면은 점진 마이그(이번 PR엔 강제 마이그 안 함 — 회귀 위험 ↓).

### SeniorButton variant API

`color: Color?` parameter 제거. 대신 `variant: SeniorButtonVariant`:

| variant | look | 의미 |
|---|---|---|
| `primary` (default) | ElevatedButton brand bg | 주된 액션 |
| `secondary` | OutlinedButton | 보조 흐름 |
| `success` | ElevatedButton success bg | "복용 완료" 같은 긍정 확정 |
| `destructive` | ElevatedButton danger bg | 삭제/취소 |

caller 마이그레이션:
- `settings_screen.dart:80` `color: AppColors.inkMute` → `variant: secondary` (spec 명시)
- `intake_check_screen.dart:48` `color: AppColors.jade` → `variant: success` (spec엔 미언급, 새 variant 추가)

success는 spec 본문 enum엔 없었지만 "복용 완료"가 brand color로 가는 건 의미상 어색해서 추가. spec에 추가하는 게 자연스러움.
