### 4. 🔴 시간 관리 삭제 버그 — systematic-debugging

#### Phase 1 — Root Cause Investigation

증상: 시간 관리 탭 → 슬롯 휴지통 → "삭제" 다이얼로그 → "삭제" 누름 → 슬롯 그대로.

대조: 약 관리 삭제는 정상 (notification 안 거침).

logcat 첫 시도 → flutter 로그 0건 (release build는 `print`/`debugPrint` 제거됨).

진단 로그 박음 (`dart:developer`는 release에서도 logcat 출력):
- `SlotsProvider.remove` ENTER/notifCancel/softDelete/items.len 단계
- `SlotRepository.softDeleteSlot` ENTER/get/save/detach 단계
- try/catch + rethrow + stacktrace

재빌드 + reinstall + logcat clear + 재현 → **로그 잡힘**:

```
E flutter : Unhandled Exception: PlatformException(error, Missing type parameter., null,
  java.lang.RuntimeException: Missing type parameter.
  at Z2.a.<init>(SourceFile:10)
  at FlutterLocalNotificationsPlugin.loadScheduledNotifications
  at FlutterLocalNotificationsPlugin.cancelNotification
  at FlutterLocalNotificationsPlugin.cancel
#3 NotificationService.cancelMany (notification_service.dart:72)
#4 SlotsProvider.remove (slots_provider.dart:47)
```

**근본 원인**: release 빌드에서 R8가 minify하면서 `flutter_local_notifications` 내부에서 Gson reflection으로 캐시 deserialize 할 때 필요한 generic type 정보를 지움. `cancel()` 호출 → `loadScheduledNotifications` → Gson TypeToken 실패 → `Missing type parameter` throw. 이 예외가 `cancelMany` → `remove` 위로 전파되어 `softDeleteSlot`이 호출되기 전에 함수 중단. slot 그대로 남음. 알려진 이슈([MaikuB/flutter_local_notifications GH issue](https://github.com/MaikuB/flutter_local_notifications/issues) 다수).

#### Phase 4 — Fix (2-layer)

**Layer 1 — Root cause**: ProGuard rules 추가
- 새 파일: [android/app/proguard-rules.pro](../../android/app/proguard-rules.pro)
- `-keep class com.dexterous.flutterlocalnotifications.**`
- `-keep class com.google.gson.reflect.TypeToken`
- `-keepattributes Signature, *Annotation*, EnclosingMethod, InnerClasses`
- [android/app/build.gradle.kts](../../android/app/build.gradle.kts) release buildType에 `isMinifyEnabled = true` + `proguardFiles(getDefaultProguardFile("proguard-android-optimize.txt"), "proguard-rules.pro")` 추가

**Layer 2 — Defense in depth**: 데이터 우선 + 알림 best-effort
- [lib/features/parent/slot/ui/slots_provider.dart](../../lib/features/parent/slot/ui/slots_provider.dart) `remove()`:
  - `_repo.softDeleteSlot` + `notifyListeners`를 **먼저** 호출 (데이터 보장)
  - notification cancel은 그 뒤 try/catch로 swallow (실패해도 사용자 영향 X)

진단 로그(`dart:developer` import 및 호출) 전부 제거 후 검증 빌드.

#### Phase 4 — Verify

수정 빌드 install → 사용자 재시도 → "잘 돼". 확인됨.
