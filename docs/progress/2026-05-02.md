## (이어서, 같은 05-02일 저녁) Google OAuth 셋업 — 사용자 manual

새 Google Cloud Console UI(Auth Platform)는 가이드 문서의 옛 경로와 메뉴가 다름. 사용자 안내 흐름:

| 단계 | 사용자 작업 | 결과 / 시행착오 |
|---|---|---|
| 1 | Supabase Authentication → Sign In/Providers → Google → Callback URL 복사 | `https://evkuwuyxqyjmaargifnx.supabase.co/auth/v1/callback` |
| 2 | Google Cloud Console → 새 프로젝트 `kyh-medi` | ✅ |
| 3 | OAuth 동의 화면 (외부 / 앱 이름 / 본인 Gmail 테스트 사용자) | ✅ (사용자 자체 진행) |
| 4 | 사용자 인증 정보 위치 못 찾음 → 새 UI는 사이드바 **클라이언트** 메뉴 | Claude가 옛 경로(API 및 서비스 → 사용자 인증 정보) vs 새 경로(Auth Platform → 클라이언트) 둘 다 안내 |
| 5 | OAuth 클라이언트 ID 만들기 → 처음에 Android 선택 → 패키지명 요구로 막힘 | 웹 애플리케이션으로 변경 안내 (Supabase OAuth flow는 server-side라 Web 타입) |
| 6 | 승인된 JavaScript 원본 칸에 Callback URL 잘못 붙여넣기 → "URI는 경로 포함 불가" 에러 | 휴지통 🗑️ 아이콘으로 칸 자체 삭제 + 승인된 리디렉션 URI 섹션에 다시 붙여넣기 |
| 7 | 만들기 → Client ID + Secret 복사 | ✅ |
| 8 | Supabase Authentication → Providers → Google → 토글 ON + Client ID/Secret 입력 + Save | ✅ "Google enabled" |
| 9 | Supabase Authentication → URL Configuration → Redirect URLs에 `io.supabase.kyhmedi://login-callback/` 등록 | ⚠️ Plan과 스킴 불일치. Claude가 정정 안내. |
| 10 | 추가로 `kyhmedi://auth-callback` 등록 (Plan 일치) | ✅ |

### 메모

- **새 Google Cloud Auth Platform UI**: 옛 가이드 문서의 "API 및 서비스 → 사용자 인증 정보" 경로가 더 이상 직관적이지 않음. 사이드바에 **클라이언트** 메뉴가 새 진입점. Claude가 이번 세션에서 안내 정정 다수.
- **승인된 JavaScript 원본 vs 승인된 리디렉션 URI 혼동**: 두 섹션이 비슷하게 생겨서 사용자가 잘못 붙여넣기 흔함. 휴지통 아이콘이 row 자체 삭제.
