### Phase 7+8 통합 emulator 검증 — 시도했으나 환경 한계

사용자가 Supabase Anonymous 토글은 사전 활성화 완료. 그래서 emulator 통합 검증 시도:

| 단계 | 결과 |
|---|---|
| `flutter build apk --debug` | ✅ 성공 |
| `pm clear` + `adb install -r` | ✅ 성공 |
| 첫 cold launch | ✅ ModeSelectScreen 정상 표시 |
| "부모님이세요?" 탭 | ❌ ANR (`kyh_medi isn't responding`) — 어제와 동일 |
| force-stop 후 재시작 | ❌ **시스템 ANR** (`Process system isn't responding`) |
| Wait + 25초 추가 대기 후 재시도 | ❌ 동일 system ANR 반복 |

logcat 진단:

```
E BLASTSyncEngine: WM sent Transaction ... never received commit callback. Application ANR likely to follow.
E Transition: Playing a Transition which hasn't started! ... This will likely cause an exception in Shell
```

ANR 발생 PID는 **27618 (system_server)** — 우리 앱 PID(24712)가 아님. 즉 안드로이드 시스템 WindowManager/Shell 자체가 응답 안 함. emulator를 15분 넘게 돌리면서 build/install/launch 반복으로 호스트 자원 압박이 누적된 결과.

**코드 수준 결론**:
- Phase 7+8 변경분(Supabase init은 어제 Phase 0부터 있던 것, Provider 2개 추가 + IntakeProvider 사전 생성 + ParentSyncService 인스턴스 1개)은 ANR 직접 원인이 아님
- 첫 cold launch에서 ModeSelectScreen은 정상 표시 (v1)
- 어제 Phase 6 검증과 동일 패턴 — 디버그 빌드 cold launch + setUserMode/Provider build의 main thread 부담
- **release 빌드(5-10배 빠름)에서는 사라질 가능성 큼** — Phase 13 Play Console 내부 테스트 빌드 시 진짜 검증
